# Learner Guide - Certified Lean Six Sigma Yellow Belt (CLSSYB) Training

## Course Overview

This learner guide supports a practical Certified Lean Six Sigma Yellow Belt course. It is designed for learners who support improvement projects, facilitate small improvement activities, map processes, collect simple data, analyze basic process performance, and help sustain countermeasures.

Yellow Belts are expected to understand Lean Six Sigma concepts more deeply than White Belts, but they usually support or facilitate scoped improvements rather than lead complex statistical projects. This course focuses on practical workplace application.

## Study Domains

The labs align with common Yellow Belt expectations:

1. Lean Six Sigma background and DMAIC.
2. Process mapping and waste identification.
3. Facilitation and Kaizen participation.
4. Basic data analysis.
5. Problem solving and root cause analysis.
6. Countermeasures and sustainment.

## Lab 01 Guide - Yellow Belt Foundations and Project Scope

### Objectives

- Explain Lean Six Sigma basics.
- Understand DMAIC.
- Describe the Yellow Belt role.
- Select and scope a small improvement project.

### Steps

1. Write your own definition of Lean.
2. Write your own definition of Six Sigma.
3. List the five DMAIC phases and one activity in each phase.
4. Compare White Belt, Yellow Belt, Green Belt, and Black Belt responsibilities.
5. Select one workplace process for the course.
6. Identify the customer affected by the process.
7. Estimate cost of poor quality such as rework, waiting, complaints, or missed opportunities.
8. Write a simple problem statement using observable facts.
9. Write a goal statement with measurable target if available.
10. Define what is in scope and out of scope.
11. Identify sponsor, process owner, and team members.
12. Record assumptions and risks.

### Deliverables

- Lean and Six Sigma definitions.
- DMAIC summary.
- Project scope worksheet.
- Problem and goal statements.
- COPQ notes.

### Checkpoint

You can explain why the project matters, what process is included, and what the Yellow Belt will support.

## Lab 02 Guide - SIPOC, Process Map, and Waste Walk

### Objectives

- Build SIPOC.
- Map the current process.
- Identify value-added and non-value-added steps.
- Identify eight wastes.

### Steps

1. Define the process start point and end point.
2. List suppliers, inputs, process steps, outputs, and customers.
3. Create a SIPOC table.
4. Draw a current-state process map.
5. Add decision points, approvals, handoffs, queues, and rework loops.
6. Mark each step as value-added, business-required, or non-value-added.
7. Review the process for transportation, inventory, motion, waiting, overproduction, overprocessing, defects, and underused skills.
8. Mark waste examples on the process map.
9. Identify the two highest-impact waste areas.
10. Decide where baseline data should be collected.

### Deliverables

- SIPOC.
- Current-state process map.
- Waste walk table.
- Measurement point notes.

### Checkpoint

You can show where waste occurs and explain which process points should be measured.

## Lab 03 Guide - Stakeholders, Facilitation, and Kaizen

### Objectives

- Identify stakeholders.
- Plan a facilitated improvement session.
- Support a Kaizen event.
- Start an A3 report.

### Steps

1. List stakeholders affected by the process.
2. Rate each stakeholder by interest and influence.
3. Identify supporters, blockers, and subject matter experts.
4. Write one engagement action for each key stakeholder.
5. Create a 60-minute meeting agenda with objective, timing, roles, and expected outputs.
6. Define ground rules for respectful facilitation.
7. Plan a Kaizen event for one scoped process issue.
8. Define pre-work, event activities, follow-up actions, and success criteria.
9. Start an A3 report with background, current condition, goal, and next steps.
10. Explain the A3 draft to a partner and revise based on feedback.

### Deliverables

- Stakeholder analysis.
- Facilitation agenda.
- Kaizen plan.
- Draft A3 report.

### Checkpoint

You can facilitate a structured discussion and document the improvement story clearly.

## Lab 04 Guide - KPIs, Data Collection, and Visuals

### Objectives

- Define a KPI.
- Create a data collection plan.
- Build run and Pareto charts.
- Use data to focus improvement.

### Steps

1. Select one primary KPI for the project.
2. Write an operational definition for the KPI.
3. Define unit, defect, opportunity, target, and data source where applicable.
4. Create a data collection plan with owner, method, frequency, and sample size.
5. Collect baseline data or use a trainer-provided dataset.
6. Check for missing values, duplicate records, and inconsistent categories.
7. Create a run chart showing performance over time.
8. Annotate known process events on the chart.
9. Create a Pareto chart for defect categories, delay reasons, or error types.
10. Identify the largest contributor and write a focus statement.

### Deliverables

- KPI definition.
- Data collection plan.
- Clean baseline data table.
- Run chart.
- Pareto chart.
- Focus statement.

### Checkpoint

You can explain the process baseline using simple data and visuals.

## Lab 05 Guide - Basic Statistics and Performance Metrics

### Objectives

- Summarize baseline data.
- Interpret variation.
- Calculate simple process performance metrics.
- Write a baseline summary.

### Steps

1. Open the baseline dataset from Lab 04.
2. Calculate count, mean, median, minimum, maximum, range, and standard deviation.
3. Create a histogram if the data is continuous.
4. Calculate yield if good units and total units are known.
5. Calculate DPU if defects and units are known.
6. Calculate DPMO if opportunities are known.
7. Compare current performance with the target.
8. Identify whether performance varies over time or by category.
9. Write a short baseline performance summary using numbers and plain language.
10. Identify one question that should move into root cause analysis.

### Deliverables

- Basic statistics table.
- Histogram if applicable.
- Yield, DPU, or DPMO worksheet.
- Baseline performance summary.

### Checkpoint

You can describe process performance using center, spread, and defect metrics.

## Lab 06 Guide - Root Cause, 5 Whys, Fishbone, and FMEA

### Objectives

- Use 5 Whys and Fishbone analysis.
- Identify evidence needed for root causes.
- Build a basic FMEA.
- Prioritize risks for countermeasures.

### Steps

1. Select the main issue from Lab 04 or Lab 05.
2. Write a fact-based problem statement.
3. Complete 5 Whys for the issue.
4. Stop when the cause becomes process-related rather than blame-based.
5. Create a Fishbone diagram using people, process, tools, materials, measurement, and environment.
6. Add possible causes to each category.
7. Circle causes that need evidence.
8. Create an FMEA for the process step most related to the problem.
9. List failure mode, effect, cause, and current controls.
10. Score severity, occurrence, and detection.
11. Calculate RPN.
12. Identify the top risks for action.

### Deliverables

- Problem statement.
- 5 Whys worksheet.
- Fishbone diagram.
- Evidence-needed list.
- FMEA.
- Prioritized risk list.

### Checkpoint

You can separate suspected causes from evidence-supported causes and show which risks need action.

## Lab 07 Guide - Countermeasures, 5S, Poka-Yoke, and Standard Work

### Objectives

- Select countermeasures linked to root causes.
- Apply 5S.
- Design simple mistake proofing.
- Draft standard work.

### Steps

1. List supported root causes and high-priority FMEA risks.
2. Brainstorm possible countermeasures.
3. Remove ideas that do not address a validated cause or risk.
4. Use an impact-effort matrix to prioritize options.
5. Select one or two countermeasures for a small test.
6. Apply 5S to the relevant workspace, queue, folder, form, or process step.
7. Identify a visual control such as a checklist, label, status board, or color code.
8. Design one poka-yoke idea to prevent or detect errors earlier.
9. Draft standard work for the improved process step.
10. Define test duration, success measure, and rollback condition.

### Deliverables

- Countermeasure list.
- Impact-effort matrix.
- 5S action list.
- Poka-yoke idea.
- Draft standard work.
- Test plan.

### Checkpoint

You can explain how each countermeasure addresses a root cause, process risk, or waste.

## Lab 08 Guide - Control Plan, A3, and Project Close

### Objectives

- Build a control plan.
- Define a response plan.
- Complete an A3 summary.
- Present the improvement story.

### Steps

1. List improved process steps that require control.
2. Define the KPI or CTQ to monitor.
3. Define target, measurement method, frequency, and owner.
4. Write a response plan for performance outside the expected range.
5. Finalize standard work instructions.
6. Define training and handover actions.
7. Compare before and after performance if pilot data is available.
8. Update the A3 report with problem, current state, analysis, countermeasure, result, and follow-up.
9. Prepare a five-minute project presentation.
10. Present to a peer or trainer and record feedback.
11. Record lessons learned and remaining risks.

### Deliverables

- Control plan.
- Response plan.
- Final standard work.
- Final A3 report.
- Presentation notes.

### Checkpoint

You can show how the improvement will be sustained and who owns the process after the project closes.
